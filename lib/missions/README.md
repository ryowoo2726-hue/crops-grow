# 과목별 퀴즈와 특별 미션 운영

## 기본 특별 미션 4종

관리자 **특별미션 선택**에서 감사 편지 보내기, 학생독립운동기념일(11월 3일), 농업인의 날(11월 11일), 순국선열의 날(11월 17일) 중 하나를 적용합니다. 직접 작성과 종료도 가능합니다. 현재 미션과 참여 기록은 관리자가 다시 적용하거나 종료할 때까지 유지됩니다. 같은 미션을 다시 적용하면 새 회차가 열리며 기존 기록은 보관합니다. 직접 작성한 미션의 성장 보상도 참가자당 회차마다 한 번 지급합니다.

세 기념일 모두 포스터 → 설명 → **문제 풀기** → 10문항 → 결과·해설 순서입니다. 모든 답은 설명에서 찾을 수 있습니다. 정답당 10%, 최대 100%를 회차마다 한 번 지급하고 남은 보상은 다음 심기로 이어집니다. 특별 퀴즈는 서버가 채점합니다. 제출 후 점수는 확정되며 재접속해도 결과와 보상 기록이 유지됩니다.

원고는 `backend/commemorative-missions.cjs`, 학생 포스터는 `special/poster.dart`입니다. 관리자 적용 시 SQLite `special_campaigns.content_json`에 설명·문제·정답을 고정합니다. 결과·선택 답안·보상은 `special_quiz_results`가 기준입니다.

감사 편지는 SQLite `gratitude_messages`에만 저장합니다. 관리자 **메시지 전송**에서 내용을 읽고 **전송**을 눌러 전달합니다. 노션에 저장하지 않고 노션 설정도 필요하지 않습니다.

받는 사람은 학생 또는 선생님입니다. 선생님께 쓸 때는 성함이나 학년부를 적을 수 있습니다. 관리자 **메시지 전송 → 감사 편지 검토**에서 작성자가 적은 이름을 확인한 뒤 **받는 선생님 선택**을 열어 등록된 선생님을 한 명 이상 체크합니다. 편지별로 전송하거나 **이 편지 선택 → 선택한 편지 전송**으로 현재 페이지의 선택 건을 한 번에 보낼 수 있습니다. 전송 내역에는 작성자가 적은 이름과 실제 수신자가 표시됩니다. 한 편지를 여러 선생님에게 보내도 작성 보상은 편지 한 건 기준입니다. 작성자는 한 회차에 서로 다른 대상에게 최대 네 건까지 쓸 수 있으며 본인에게는 보낼 수 없습니다.

메시지 버튼의 숫자·테두리는 안 읽은 전달 완료 메시지 수입니다. 받은함을 열기만 하면 읽음 처리하지 않고 개별 카드를 펼칠 때 저장합니다. 학생은 학년·반·번호, 선생님은 성함으로 본인 메시지만 받습니다. 읽은 본문은 보관하고 숫자와 강조만 없앱니다. 기존 활성 화면 60초 갱신과 다시 활성화 시 조회로 새 메시지를 반영합니다.

특별 퀴즈 보상은 서버에서 확정하고 결과 창을 닫을 때 영양분 흡수 효과를 보여줍니다. 같은 결과를 다시 열어도 효과·보상은 반복하지 않습니다. 단어 단위 줄바꿈은 `lib/word_text.dart`에서 처리하며 한 줄보다 긴 단어는 화면 안에서 나눕니다. 모바일 키보드가 열려도 게임 배율을 유지하고 감사 입력칸을 자동 스크롤합니다.

## 과목별 퀴즈 등록

운영 문제은행 `backend/content/quiz-bank.json`에는 과학·역사·영어가 각각 12세트씩, 한 세트에 10문제씩 들어 있습니다. 활성 출제 범위는 총 36세트 360문제입니다.

운영 서버의 해당 파일을 수정하면 학생이 다음에 과목 목록이나 퀴즈를 열 때 SQLite에 자동 반영합니다. JSON이 잘못되면 서버 콘솔에 기록하고 마지막으로 등록한 문제를 사용합니다. 별도의 테스트 서버에는 아래 명령으로 예시를 넣을 수 있습니다.

```powershell
Copy-Item backend/quiz-bank.template.json backend/content/quiz-bank.json
```

파일은 `sets` 배열 안에 세트를 추가하는 형식입니다. 각 세트에는 다음 항목을 작성합니다.

- `id`는 `english-001` 같은 고유한 값입니다. 기존 세트의 정답·보기·해설을 수정할 때 같은 id를 유지합니다.
- `subject`는 `영어`, `과학`, `역사` 같은 과목 이름입니다. 새 과목도 이 항목으로 추가할 수 있습니다. 기존 id의 과목은 유지합니다.
- `title`은 교사가 구분할 세트 제목입니다.
- `active`를 `false`로 바꾸면 새 출제를 중단합니다. 이미 배정한 문제와 풀이 기록은 유지합니다.
- `questions`에는 정확히 10문제를 넣습니다. 각 문제의 `question`, 서로 다른 `choices` 4개, `correctIndex` 0~3, 선택 항목인 `explanation`을 작성합니다. 정답 번호는 첫 번째 보기가 0입니다.

과목별 120문제는 10문제 세트 12개로 작성합니다. 같은 과목의 여러 세트에 같은 문제를 중복 등록하면 오류로 안내합니다. 기존 세트의 id를 바꾸면 새 세트로 취급하므로, 내용 수정 시 id를 유지하세요. 새 문제 10개를 추가할 때 새 id를 부여합니다. `backend/content/`의 실제 문제 파일은 Git 업로드에서 제외됩니다.

파일에서 생략한 기존 세트는 DB에 남아 있습니다. 출제를 중단하려면 해당 세트의 `active`를 false로 지정하세요. 이미 학생에게 배정한 문제는 당시의 문제·정답을 보관해 풀이 중 교사의 수정에 영향을 받지 않습니다.

파일 경로를 직접 지정해서 등록할 수도 있습니다.

```powershell
node backend/manage.cjs import-quiz-bank backend/content/quiz-bank.json
```

## 학생 풀이와 성장

학생은 미션 → 퀴즈 미션 → 과목을 선택합니다. **한국 시간 오전 8시부터 다음 날 오전 8시 전까지 과목당 한 세트, 10문제**를 풉니다. 영어를 완료해도 같은 기간에 과학·역사는 각각 한 세트씩 풀 수 있습니다. 과목 선택 시 SQLite에 보관된 문제·보기·정답·해설 10개를 한 번에 받고, 문제를 넘기는 동안 추가 서버 요청이 발생하지 않습니다. 기기에서 정답 수 × 10%를 계산하고 `POST /api/quiz-runs/submit`에 `{runId, growth}`만 보냅니다. 서버 응답도 결과 요약과 보상 수령 여부만 보내며 문제를 다시 전송하지 않습니다. 제출 전에는 답을 바꿀 수 있고 제출 후 점수는 확정됩니다. 오답·0점도 해당 세트 완료로 기록합니다.

서버는 배정 기록의 소유자, 날짜, 성장률 0~100(10 단위), 중복 제출·보상을 검사합니다. 사용자가 선택한 기기 채점 방식이므로 조작된 성장률을 판별할 수는 없습니다. 기존에 열어 둔 프론트의 답 10개 일괄 제출도 호환용으로 받습니다.

성장률 값은 완료 요약으로 한 번만 제출합니다. 결과 창을 닫을 때 기존 성장 처리 API에는 `runId`와 요청 번호만 보냅니다. 채점 응답을 기다리는 동안 창을 닫아도 채점이 끝나면 보상을 한 번 적용합니다. 서버에서 이전 날짜의 퀴즈에 미수령 보상이 있으면 과목 목록에 **지난 퀴즈 보상 받기**가 표시됩니다. 받을 보상과 풀 세트가 모두 없는 과목은 **새 문제 준비 중**으로 표시되고 선택 버튼이 비활성화됩니다.

참가자마다 아직 배정받지 않은 세트 중 하나를 무작위로 뽑습니다. 서로 다른 참가자는 같은 세트를 받을 수 있습니다. 제출하지 않은 세트도 배정 이력에 포함하며, 교사가 문제를 다른 세트로 옮겼을 때도 이전에 배정한 문항을 확인합니다. 모든 세트를 소진하면 새 문제가 등록될 때까지 기다립니다. 오전 8시 전에는 창을 닫거나 새로고침해도 해당 이용 기간에 배정된 세트를 다시 받습니다. 제출 전 선택한 보기는 창을 닫으면 다시 선택해야 합니다.

과목별 하루 10문제를 끝내면 과목 목록과 결과 화면에 원형 완료 도장을 표시합니다. 제출 직후 결과 화면에서 자신의 답·정답·해설을 확인합니다. 정답은 초록색 체크와 테두리, 오답은 빨간색 X와 테두리로 구분하며 실제 정답은 초록색으로 표시합니다. 선택 답안은 기기 메모리에만 있어 팝업을 다시 열거나 재접속하면 총점·정답·해설만 표시합니다. 서버에는 완료한 세트와 성장률 요약을 보관합니다. 정답 수 × 10%의 성장 보상은 결과 창을 닫을 때 기존 영양분 애니메이션으로 한 번에 적용합니다. X 버튼이나 바깥 클릭으로 닫아도 같은 동작입니다. 채점 직후에는 성장하지 않습니다. 0점도 하루 풀이 완료로 처리하며 성장 보상은 없습니다.

성장도는 작물당 최대 100%입니다. 일일·기념일 퀴즈 보상 중 작물에 들어가지 않은 영양분은 SQLite에 보관하며, 수확할 때와 밭이 비어 있을 때 남은 양이 표시됩니다. 새 씨앗을 심으면 영양분이 뿌리로 들어가면서 성장 게이지가 올라갑니다. 한 번에 100%를 채우고도 남으면 다음 심기까지 보관합니다. 이미 채점을 마치고 결과를 닫기 전에 접속이 끊긴 일일 퀴즈도 다음 심기에서 자동 지급합니다. 퀴즈의 일일 제한은 물 주기·특별 미션 제한과 별도로 적용합니다.

## 특별 미션과 이전 퀴즈

운영 특별 미션은 관리자 웹의 **특별미션 선택 → 적용**에서 열고 **특별미션 종료 → 적용**에서 닫습니다. 기존 서버와 로컬 체험에 사용하는 `backend/special.template.json` 형식도 읽을 수 있습니다.

```powershell
node backend/manage.cjs import-special backend/content/특별미션.json
```

기존 주간 퀴즈 DB와 API는 이전 데이터 호환용으로 남아 있습니다. 새 프론트는 과목별 퀴즈를 사용하며, 문제은행을 등록한 서버는 이전 방식의 퀴즈 보상 요청을 거절합니다. 백엔드와 새 프론트를 함께 적용하세요. 로컬 단독 테스트 모드는 기존 예시 퀴즈를 사용합니다.

## 검증과 저장

공식 문제·채점 결과·완료 이력·보상 수령 여부는 SQLite가 기준입니다. SQLite 스키마 v2에 `quiz_sets`, `quiz_runs`를 추가하며 기존 학생·수확 기록을 유지합니다. 기존 운영 DB를 업데이트하기 전 백업 명령을 사용하세요.

검증은 `flutter analyze`, `flutter test`, `node --test backend/backend.test.cjs`와 `tests/flutter.browser.test.cjs`를 사용합니다. 퀴즈 화면은 `quiz/set_popup.dart`, API 연결과 영양분 효과는 `lib/main.dart`, 서버 판정은 `backend/quiz-bank.cjs`에서 관리합니다.

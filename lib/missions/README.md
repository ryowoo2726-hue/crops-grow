# 과목별 퀴즈와 특별 미션 운영

## 과목별 퀴즈 등록

현재 PC의 `backend/content/quiz-bank.json`을 수정하고 저장하면 됩니다. 영어·과학·역사 예시 세트를 각 10문제씩 준비했습니다. 학생이 다음에 과목 목록이나 퀴즈를 열 때 변경한 내용을 SQLite에 자동 반영합니다. JSON 오류가 있으면 서버 콘솔에 안내하고 마지막으로 정상 등록한 문제를 사용합니다.

새 서버에서는 예시 파일을 먼저 복사합니다.

```powershell
Copy-Item backend/quiz-bank.template.json backend/content/quiz-bank.json
```

파일은 `sets` 배열 안에 세트를 추가하는 형식입니다. 각 세트에는 다음 항목을 작성합니다.

- `id`는 `english-001` 같은 고유한 값입니다. 기존 세트의 정답·보기·해설을 수정할 때 같은 id를 유지합니다.
- `subject`는 `영어`, `과학`, `역사` 같은 과목 이름입니다. 새 과목도 이 항목으로 추가할 수 있습니다. 기존 id의 과목은 유지합니다.
- `title`은 교사가 구분할 세트 제목입니다.
- `active`를 `false`로 바꾸면 새 출제를 중단합니다. 이미 배정한 문제와 풀이 기록은 유지합니다.
- `questions`에는 정확히 10문제를 넣습니다. 각 문제의 `question`, 서로 다른 `choices` 4개, `correctIndex` 0~3, 선택 항목인 `explanation`을 작성합니다. 정답 번호는 첫 번째 보기가 0입니다.

과목별 100문제는 10문제 세트 10개로 작성합니다. 같은 과목의 여러 세트에 같은 문제를 중복 등록하면 오류로 안내합니다. 기존 세트의 id를 바꾸면 새 세트로 취급하므로, 내용 수정 시 id를 유지하세요. 새 문제 10개를 추가할 때 새 id를 부여합니다. `backend/content/`의 실제 문제 파일은 Git 업로드에서 제외됩니다.

파일에서 생략한 기존 세트는 DB에 남아 있습니다. 출제를 중단하려면 해당 세트의 `active`를 false로 지정하세요. 이미 학생에게 배정한 문제는 당시의 문제·정답을 보관해 풀이 중 교사의 수정에 영향을 받지 않습니다.

파일 경로를 직접 지정해서 등록할 수도 있습니다.

```powershell
node backend/manage.cjs import-quiz-bank backend/content/quiz-bank.json
```

## 학생 풀이와 성장

학생은 미션 → 퀴즈 미션 → 과목을 선택합니다. 서울 날짜 기준으로 **과목당 하루 한 세트, 10문제**를 풉니다. 영어를 완료해도 같은 날 과학·역사는 각각 한 세트씩 풀 수 있습니다. 과목 선택 시 SQLite에 보관된 문제·보기·정답·해설 10개를 한 번에 받고, 문제를 넘기는 동안 추가 서버 요청이 발생하지 않습니다. 기기에서 정답 수 × 10%를 계산하고 `POST /api/quiz-runs/submit`에 `{runId, growth}`만 보냅니다. 서버 응답도 결과 요약과 보상 수령 여부만 보내며 문제를 다시 전송하지 않습니다. 제출 전에는 답을 바꿀 수 있고 제출 후 점수는 확정됩니다. 오답·0점도 해당 세트 완료로 기록합니다.

서버는 배정 기록의 소유자, 날짜, 성장률 0~100(10 단위), 중복 제출·보상을 검사합니다. 사용자가 선택한 기기 채점 방식이므로 조작된 성장률을 판별할 수는 없습니다. 기존에 열어 둔 프론트의 답 10개 일괄 제출도 호환용으로 받습니다.

성장률 값은 완료 요약으로 한 번만 제출합니다. 결과 창을 닫을 때 기존 성장 처리 API에는 `runId`와 요청 번호만 보내고 성장률을 다시 보내지 않습니다. 백엔드가 저장된 보상을 한 번 적용하며 화면은 응답의 최종 성장도로 교체합니다. 기기에서 별도로 성장도를 더하지 않습니다.

완료한 세트는 해당 학생의 다음 출제에서 제외합니다. 이전 풀이에 나온 문제 문장도 확인하여, 교사가 세트를 수정하거나 문제를 다른 세트로 옮겼을 때 이미 푼 문제가 다시 나오지 않도록 합니다. 모든 세트를 소진하면 새 문제가 등록될 때까지 기다립니다. 중간에 창을 닫거나 새로고침하면 같은 날짜의 같은 세트를 다시 받습니다. 제출 전 선택한 보기는 창을 닫으면 다시 선택해야 합니다.

제출 직후 결과 화면에서 자신의 답·정답·해설을 확인합니다. 선택 답안은 기기 메모리에만 있어 팝업을 다시 열거나 재접속하면 총점·정답·해설만 표시합니다. 서버에는 완료한 세트와 성장률 요약을 보관합니다. 정답 수 × 10%의 성장 보상은 결과 창을 닫을 때 기존 영양분 애니메이션으로 한 번에 적용합니다. X 버튼이나 바깥 클릭으로 닫아도 같은 동작입니다. 채점 직후에는 성장하지 않습니다. 0점도 하루 풀이 완료로 처리하며 성장 보상은 없습니다.

성장도는 작물당 최대 100%입니다. 남은 성장량보다 큰 보상은 100%까지 적용합니다. 이미 100%이거나 작물이 없으면 보상을 보관하고, 수확·다시 심기를 마친 뒤 해당 과목의 결과를 다시 열어 닫을 때 받습니다. 미수령 보상은 다음 날과 재접속 뒤에도 유지됩니다. 같은 과목에서 이전 보상이 남아 있으면 그 결과를 먼저 보여줍니다. 퀴즈의 일일 제한은 물 주기·특별 미션 제한과 별도로 적용합니다.

## 특별 미션과 이전 퀴즈

특별 미션은 기존 `backend/special.template.json` 형식으로 등록합니다.

```powershell
node backend/manage.cjs import-special backend/content/특별미션.json
```

기존 주간 퀴즈 DB와 API는 이전 데이터 호환용으로 남아 있습니다. 새 프론트는 과목별 퀴즈를 사용하며, 문제은행을 등록한 서버는 이전 방식의 퀴즈 보상 요청을 거절합니다. 백엔드와 새 프론트를 함께 적용하세요. 로컬 단독 테스트 모드는 기존 예시 퀴즈를 사용합니다.

## 검증과 저장

공식 문제·채점 결과·완료 이력·보상 수령 여부는 SQLite가 기준입니다. SQLite 스키마 v2에 `quiz_sets`, `quiz_runs`를 추가하며 기존 학생·수확 기록을 유지합니다. 기존 운영 DB를 업데이트하기 전 백업 명령을 사용하세요.

검증은 `flutter analyze`, `flutter test`, `node --test backend/backend.test.cjs`와 `tests/flutter.browser.test.cjs`를 사용합니다. 퀴즈 화면은 `quiz/set_popup.dart`, API 연결과 영양분 효과는 `lib/main.dart`, 서버 판정은 `backend/quiz-bank.cjs`에서 관리합니다.
